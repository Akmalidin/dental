# Дашборд «Сегодня»: касса, загрузка врачей, новые заявки

Дата: 2026-08-11
Статус: утверждено, план реализации следующим шагом

## Контекст

В новом интерфейсе (`templates/newui/`, роуты `/new/*`) уже есть страница
дашборда (`newui_dashboard` → `apps/users/views.py:_newui_dashboard_data()` →
`templates/newui/dashboard.html`): выручка сегодня/вчера, пациенты сегодня,
новые пациенты за месяц, заказы лаборатории, график выручки за неделю,
последние пациенты, ближайшие приёмы сегодня.

Изначальный запрос («Dashboard Сегодня + Быстрые действия + Онбординг тенанта»)
был написан под гипотетический стек (DRF-API + Vue3-SPA + django-tenants +
Celery). Реальный стек — Django-монолит с серверным рендерингом,
мультиклиничность — логическая (`clinic` FK + thread-local, см.
`apps/tenancy.py`), а не schema-per-tenant. Быстрые действия (создание записи,
приём оплаты, смена статуса, открытие/закрытие смены) уже реализованы как
обычные Django-эндпоинты и используются в старом интерфейсе и в
`schedule.html`/`cashdesk.html` нового:

- `appointment_create_quick`, `appointment_status` (apps/appointments/urls.py)
- `cashshift_open`, `cashshift_close`, `payment_create` (apps/finance/urls.py)

Онбординг тенанта в этом продукте — форма суперадмина (`superadmin_panel`,
action=`create_clinic`), не self-serve визард; при создании клиники уже
автоматически создаются: роль admin_main, главный филиал, опционально —
демо-данные (`seed_dental()`). Self-serve онбординг-мастера нет и в рамках
этой задачи не создаётся.

**Вывод по скоупу** (см. диалог брейнсторминга): в первую очередь делаем
только расширение дашборда тремя виджетами (касса / загрузка врачей / новые
заявки). Inline-действия на карточках записей и онбординг-чеклист — вне
скоупа этой итерации, могут стать отдельными задачами позже.

## Архитектура

Никаких новых моделей, миграций или URL. Используются существующие:
`apps.finance.models.CashShift` (+`z_report()`), `apps.users.models_salary.DoctorSchedule`,
`apps.patients.models.Lead`.

### Backend — `apps/users/views.py`

`_newui_dashboard_data()` пополняется тремя ключами через новые приватные
хелперы:

```
_dashboard_cash_summary(clinic) -> {
  opened: bool, openedAt: str|None, openedBy: str|None,
  incomeTotal: float, refundTotal: float, balance: float,
}
```
Филиал определяется той же логикой, что в `_cashier_branch`/`_newui_cashdesk_data`
(главный филиал клиники, иначе первый попавшийся). Если открытой смены нет —
`opened=False`, остальные поля `0`/`None`. `balance` = `expectedCash` из
`CashShift.z_report()` (opening_cash + приход наличными − возврат наличными).

Отклонение от исходного промпта: `expense_total` не считаем — `Expense` в
этой кодовой базе не привязан к смене (датированная сущность, отдельная от
кассовой смены), плодить для дашборда новую агрегацию по датам не по месту.

```
_dashboard_doctors_load(clinic) -> [
  { doctorId, name, occupancyPct: int },
  ...
]
```
Только врачи с `DoctorSchedule(is_working=True)` на сегодняшний день недели
(`date.weekday()` совпадает с `DoctorSchedule.day_of_week`). На врача:
доступные минуты = сумма (`end_time` − `start_time`) по всем его рабочим
записям графика на сегодня (если врач числится в нескольких филиалах);
занятые минуты = сумма длительностей его `Appointment` на сегодня, кроме
`STATUS_CANCELLED`. `occupancyPct = round(занято/доступно*100)`. Врачи без
графика на сегодня в список не попадают (не «0%», а отсутствуют — это не
рабочий день). Сортировка — по убыванию `occupancyPct`.

```
_dashboard_funnel_new(clinic, limit=10) -> [
  { id, name, phone, createdAt: str },
  ...
]
```
`Lead.objects.filter(stage=Lead.STAGE_NEW).order_by("-created_at")[:limit]`.

### Frontend — только `templates/newui/dashboard.html`

`templates/newui/base.html` не редактируется (параллельно с ним прямо сейчас
работает другая сессия Claude Code над переводом — по договорённости избегаем
конфликта, весь новый CSS/JS живёт только в dashboard.html).

- Три новые карточки в стиле существующих `.card`/`.kpi` классов из base.html,
  новой строкой после блока «Ближайшие приёмы сегодня»:
  - **Касса** — статус (открыта/закрыта), приход, возврат, баланс; если
    закрыта — просто пометка, без формы открытия на дашборде. Ссылка
    «Касса →» на `/new/cashdesk/` (тем же паттерном, что «Финансы →»,
    «Пациенты →», «Расписание →» уже на странице).
  - **Загрузка врачей** — список врачей с горизонтальным прогресс-баром и %.
  - **Новые заявки** — последние необработанные лиды (имя, телефон, когда).
    Ссылка «Заявки →» на `/new/funnel/`. Без кнопки «взять в работу» —
    read-only сводка (вне скоупа этой итерации).
- Данные приходят уже существующим каналом: `real_data` → `{{ real_data|json_script:"newui-real-data" }}`
  в base.html → глобальная переменная `dashboardData` (заполняется IIFE в
  base.html из `data.dashboard`, `renderDashboard()` уже вызывается один раз
  при загрузке страницы — поллинга нет, это серверный рендеринг, не SPA).
- dashboard.html получает свой `{% block extra_js %}` (сейчас пустой) —
  читает `dashboardData.cashSummary`/`.doctorsLoad`/`.funnelNew` и рендерит
  три новых блока. Выполняется после IIFE в base.html (блок физически ниже
  в шаблоне), так что `dashboardData` уже заполнен к этому моменту.

- Точечный тест в `apps/users/tests.py` (уже модифицируется в этой ветке):
  фикстуры клиники/филиала/врача с `DoctorSchedule`, открытая `CashShift`,
  пара `Lead` — проверяем, что `_newui_dashboard_data()` возвращает три новых
  ключа с ожидаемыми значениями (open/closed смена, % загрузки, список
  заявок).
- Существующий `apps/users/test_newui_smoke.py` (проверяет `/new/` → 200)
  должен продолжать проходить без изменений — регрессионная защита от
  конфликта с параллельной сессией, редактирующей `templates/newui/*`.

## Вне скоупа этой итерации

- Inline-действия на карточках записей (оплатить/пришёл/начать приём) —
  бэкенд для них уже существует (`appointment_create_quick`,
  `appointment_status`, `payment_create`), фронтенд-обвязка на дашборде не
  делается сейчас.
- Онбординг-чеклист/визард для новых клиник.
- Всё, что описано во втором (Vue3/DRF) промпте пользователя — см. отдельное
  обсуждение целевой UI-поверхности ниже.

## Примечание: Vue3-промпт (frontend/) — решено, вне скоупа

В репозитории есть третий UI-слой: `frontend/` — мини-SPA на Vue 3 + Vite +
Pinia + vue-router, с страницами Dashboard/Patients/Appointments/Calendar/
Treatments/Finance, собирается в `../static/js/vue/app.js`. Ни один шаблон
Django этот бандл не подключает, и сама папка `static/js/vue` отсутствует
(не собрана) — код мёртв, отдельно от активно разрабатываемого
`templates/newui/`. Пользователь прислал второй (Vue-ориентированный) промпт
«Dashboard Сегодня» для этого стека — подтверждено: `frontend/` мёртв,
промпт не реализуем. Вся работа по этой итерации — только в `templates/newui/`
и `apps/users/views.py`, как описано выше.
